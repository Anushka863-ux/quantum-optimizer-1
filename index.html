1Shor’s algorithm: factoring

Problem: given N = p × q, find p and q. No fast classical method is known, and RSA security depends on this. Shor’s idea: turn factoring into period finding, and find the period with the quantum Fourier transform (QFT).

In simple words Take a number a and keep multiplying it by itself, always keeping the remainder after dividing by N. The remainders repeat in a loop, like a song’s rhythm. Once you know how long that loop is (the period r), a little school maths (gcd) gives you the two factors. Finding the period is the hard part. A quantum computer tries every x at once, and the QFT makes the rhythm show up as tall spikes.

Classical: trial division

Shor: steps

Step 1: f(x) = aˣ mod N repeats

Each dot is one value of aˣ mod N. The pattern repeats every r steps. Green dots are the values left after the measurement in step 3.

Step 2: what we measure after the QFT

Almost all the probability sits on a few spikes spaced Q/r apart. The dashed line is what a random guess would give. Measuring lands on a spike, and from its position we work out r.

Why factoring is hard: work needed as the number gets bigger

The y axis is a log scale (each step up = 10× more work). Classical = the best known method (GNFS). Shor = about (log N)³ gates. For 2048-bit RSA, classical is practically impossible, while Shor needs about 10¹⁰ gates but also a very large error-corrected quantum computer.

2Delivery route optimization (TSP / VRP)

6 cities (city 0 = warehouse), so 5! = 120 possible routes. Three approaches: brute force, greedy, and QAOA (simulated).

In simple words
  1. Brute force checks every possible route. Always right, but impossible for many cities.
  2. Greedy always drives to the nearest unvisited city. Fast, but can miss the best route.
  3. QAOA starts with every route equally likely. Each layer turns up the “volume” on short routes and turns down long ones, so when we measure, a short route is more likely to come out.

Solid green = best route found. Dashed red = greedy route. Black dot = warehouse.

QAOA route probabilities (routes sorted from shortest to longest)

At the start all 120 routes are equally likely (dashed line). After QAOA, the bars on the left (short routes) are taller. The green bar is the best route. A real quantum computer would need n² qubits for this, so 36 qubits for 6 cities.

How the search space grows with the number of cities

Log scale again. Checking every route grows as (n−1)!, which explodes. The best exact method (Held-Karp) grows as n²·2ⁿ. The number of qubits QAOA needs grows only as n², but fewer qubits does not automatically mean a faster answer.

Bonus: VRP with 2 vehicles

Same cities, but two vans leave the warehouse. Goal: make the slower van finish as early as possible. Brute force tries all 30 ways to split the customers and every visiting order inside each split.

In simple words Now we have to decide two things: which shops each van takes, and in what order. That extra choice multiplies the possibilities again, which is why VRP is harder than TSP.

3Quantum annealing demo (14-city route)

A quantum annealer starts with all routes in superposition and slowly lowers a transverse field Γ, so the system can tunnel between routes and settle in a low-cost one. Here it is simulated with simulated quantum annealing (SQA, path-integral Monte Carlo): 8 linked copies of the route whose link gets stronger as Γ falls. It is compared with ordinary simulated annealing (SA) and the exact best answer (Held-Karp).

In simple words Picture a ball rolling over hills, looking for the lowest valley (the shortest route). Simulated annealing shakes the ball so it can jump over hills, and shakes less and less over time. Quantum annealing lets the ball tunnel through hills instead of climbing over them, which can help it escape a bad valley.
Running…

Y axis: best route length found so far, in units of the average city distance. Lower is better, and the dashed line is the perfect answer. This is a classical simulation of the physics; a real annealer such as D-Wave uses physical qubits. Results change every run, and SQA does not always win.

4Summary

ClassicalQuantum
FactoringSub-exponential (GNFS); 2048-bit is practically impossibleShor: polynomial, proven exponential speedup
TSP / VRPNP-hard; exact methods cost (n−1)! or n²2ⁿ; heuristics are approximateQAOA / annealing: heuristic, advantage not yet proven
HardwareAvailable todayShor needs error-corrected qubits. QAOA runs small instances on today’s noisy (NISQ) devices
In one lineShor’s speedup is proven but waits for hardware. For routing, quantum methods are promising but not yet proven better.

5Qiskit code (for a real device or simulator)

Tested with Qiskit 2.6 and qiskit-optimization 0.7.

QAOA for routing (QUBO → Ising)

# pip install qiskit qiskit-optimization
import numpy as np
from qiskit_optimization.applications import Tsp
from qiskit_optimization.converters import QuadraticProgramToQubo
from qiskit_optimization.minimum_eigensolvers import QAOA
from qiskit_optimization.optimizers import COBYLA
from qiskit.primitives import StatevectorSampler

n = 4
tsp = Tsp.create_random_instance(n, seed=1)
qp = tsp.to_quadratic_program()          # n^2 binary vars
qubo = QuadraticProgramToQubo().convert(qp)
op, offset = qubo.to_ising()
qaoa = QAOA(StatevectorSampler(seed=1), COBYLA(maxiter=100), reps=3)
res = qaoa.compute_minimum_eigenvalue(op)
bits = res.best_measurement["bitstring"]
x = np.array([int(b) for b in bits[::-1]])   # Qiskit bit order is reversed
print("QAOA route:", tsp.interpret(x))     # e.g. [0, 3, 2, 1]

Shor (order finding, N = 15)

from math import gcd
from fractions import Fraction
from qiskit import QuantumCircuit
from qiskit.circuit.library import QFTGate
from qiskit.primitives import StatevectorSampler

def c_mult7_mod15(power):               # controlled "multiply by 7^power mod 15"
    U = QuantumCircuit(4)
    for _ in range(power):
        U.swap(2, 3); U.swap(1, 2); U.swap(0, 1)
        U.x(range(4))
    return U.to_gate(label=f"7^{power}").control()

t = 8                                   # counting qubits
qc = QuantumCircuit(t + 4, t)
qc.h(range(t)); qc.x(t)                 # second register starts at |1>
for k in range(t):
    qc.append(c_mult7_mod15(2**k % 4), [k] + list(range(t, t + 4)))
qc.append(QFTGate(t).inverse(), range(t))
qc.measure(range(t), range(t))

counts = StatevectorSampler(seed=1).run([qc], shots=64).result()[0].data.c.get_counts()
for bits in counts:
    r0 = Fraction(int(bits, 2) / 2**t).limit_denominator(15).denominator
    r = next((m * r0 for m in range(1, 8) if pow(7, m * r0, 15) == 1), None)
    if r and r % 2 == 0 and pow(7, r // 2, 15) != 14:
        h = pow(7, r // 2, 15)
        print("period r =", r, "-> factors", gcd(h - 1, 15), gcd(h + 1, 15)); break
# output: period r = 4 -> factors 3 5

Classical baseline (Held-Karp DP, exact)

from functools import lru_cache
def tsp(d):
    n=len(d)
    @lru_cache(None)
    def f(mask,i):
        if mask==(1<<n)-1: return d[i][0]
        return min(d[i][j]+f(mask|1<<j,j) for j in range(n) if not mask&1<<j)
    return f(1,0)

6Limitations

Shor: The maths is proven, but breaking 2048-bit RSA needs a fault-tolerant quantum computer (recent estimates are under about a million noisy qubits). Today’s devices have only factored tiny numbers like 15 or 21.

Routing: QAOA and quantum annealing (D-Wave) give approximate answers. There is no proven advantage yet, because classical solvers (OR-Tools, LKH) are very good. The honest description is “hybrid quantum-classical, ready for future hardware”, not “quantum is already better”.

The real value of this project: explaining and comparing the mechanism behind both problems, plus a QUBO formulation that can run on any quantum backend.
